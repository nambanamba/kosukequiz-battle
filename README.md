# kosukequiz-battle

中学受験（四谷大塚「予習シリーズ」5年下）の一問一答クイズアプリです。1対1のリアルタイム早押し対戦（社会・理科の暗記系）と、一人で解く自習モードを備えます。GitHub Pagesでホストする静的サイトで、対戦相手同士の通信は [Trystero](https://trystero.dev/)（サーバーレスWebRTC）でブラウザ間を直接つなぎます。バックエンドサーバーやアカウント登録は不要です。

旧姉妹アプリ「kosukequiz」（社会のみ・対戦機能なし）は2026-08-29に廃止し、本アプリに一本化しました。以降、社会・理科の暗記系問題データはこのリポジトリの `data.js` が唯一のソースです。

理科の「今日の計算問題」と社会の「今日の漢字プリント」は、2026-09-03に姉妹アプリへ切り出しました（詳しくは下記「姉妹アプリ」参照）。本アプリのホーム画面には、それぞれへのリンクだけが残っています。

## 遊び方

1. ホーム画面で科目（社会／理科）を選ぶ
2. 一方が「部屋をつくる」で出題する単元・問題数を選び、発行された4桁のコードをもう一方に伝える → もう一方が「部屋に入る」で参加 → 早押しボタンで解答権を取り合い、答え合わせは口頭で行い、押さなかった側が〇✕を判定する（一人で解く「一人で始める」モードもあり）
3. 「こどもどうし公平モード」（ホーム画面のトグル）：親子戦とちがい、部屋をつくった側による問題の先読み・スキップを行わず、問題は両者に同時配信される。相手が参加すると、相手側でも出したい単元を選べ、部屋をつくった側が選んだ単元と合わせて出題される（相手が単元を選ばなければ、部屋をつくった側の選択のみで出題）
4. 復習ミックス：メインで選んでいない単元から、復習する単元・出題タイプ・優先度・難易度を指定して追加出題できる。並び順は「①一度も正解していない問題→②正解より失敗が多い問題（最後に正解した日が古い順）→③失敗経験はあるが正解の方が多い問題（同様に古い順）→④一度も失敗していない問題（同様に古い順）」の苦手優先方式（ランダム要素なし）

## 姉妹アプリ

このアプリ本体からは独立した、印刷・書き取り練習に特化した姉妹アプリです。ホーム画面から各アプリへのリンクがあります。

- **[kanji-print-app](https://github.com/nambanamba/kanji-print-app)**（社会・今日の漢字プリント）：https://nambanamba.github.io/kanji-print-app/
- **[keisan-print-app](https://github.com/nambanamba/keisan-print-app)**（理科・今日の計算問題）：https://nambanamba.github.io/keisan-print-app/
- **[kanji](https://github.com/nambanamba/kanji)**（国語・漢字と言葉）：https://nambanamba.github.io/kanji/

いずれもGitHub Pagesの同一オリジン（`nambanamba.github.io`）でホストしているため、localStorageはこのアプリと自動的に共有されます（漢字プリントの進捗記録など）。

## data.js の更新方法

このリポジトリの `data.js`／`images/` が社会・理科の暗記系問題の唯一のソースです。新しい問題データは `5年下\quiz_csv\`（社会）・`5年下\quiz_csv_理科\`（理科）で作成したJSONを、このリポジトリのdata.js取り込み担当セッションが直接反映します。

- 理科の計算問題（`kind:"calc"`）は、このリポジトリの`data.js`には**含めません**。`keisan-print-app`の`data.js`に反映してください
- 社会の漢字プリント用データ（`第{回}回_漢字.json`）は、このリポジトリの`data.js`には**含めません**。`kanji-print-app`の`kanji-data.js`に反映してください

### data.js のスキーマ（QA_DATA）

```js
{ id, subj, u, q, a, img?, kai?, kind?, sol?, note? }
```

- `subj`：`"社会"` | `"理科"`（必須）
- `kind`：`"memo"`（暗記・省略時のデフォルト）。理科の計算問題（`kind:"calc"`）はこのリポジトリには含めない（上記参照）
- `kai`：回番号（理科のみ）
- `note`：出典（例：`本文、7P`）。存在すればクイズ画面に「出典：〇〇」と小さく表示される。省略可
- id接頭辞：社会は `t`/`z`/`s`・`simg`/`g`、理科は `r{回}m{連番}`（暗記のみ。計算問題の`r{回}c{連番}`はkeisan-print-app側）。衝突厳禁（`stats`/`edits` はidキーで永続化されるため）

## 動作確認（変更したら流してください）

テストは3種類あります。**まず速いほうから流してください。**

### 1. 素早い確認（123件・3秒未満・準備なし）

```
node tools/test_settings_by_subject.mjs   # 科目ごとの設定保存（16件）
node tools/test_solo_session_by_id.mjs    # 中断したひとり練習（20件）
node tools/test_reveal_sync.mjs           # こたえの同時オープン（21件）
node tools/test_list_meta_filter.mjs      # 問題一覧の優先度・難易度（21件）
node tools/test_sounds.mjs                # 正解音・不正解音・わかった通知（23件）
node tools/test_migration.mjs             # 旧単元から復習編への記録の引きつぎ（22件）
```

**`index.html` から実物の関数を名前で切り出して動かす**ので、書き写したコードではなく実コードを
検証します。行番号に依存していないので、`index.html` を編集してもズレません。
**node だけで動き、インストールは要りません。**`index.html` を触ったら毎回これを流してください。

ブラウザを使わないぶん、**見た目や画面の操作そのものは見ていません。**そこは下の2で見ます。

### 2. じっくり確認（11件・約95秒・playwright が必要）

```
node tools/smoke-test.mjs              # 全部
node tools/smoke-test.mjs 単元 CSV     # 名前に「単元」か「CSV」を含むものだけ
```

すべて通れば終了コード0、ひとつでも失敗すれば1を返すので、そのまま自動化にも使えます。
**実ブラウザで実際の画面を操作する**ので、1より忠実です。そのぶん時間がかかります。

初回は `npm i playwright` と `npx playwright install chromium` が必要です
（**数百MBのダウンロード**になります）。`node_modules` はリポジトリに入れないでください（`.gitignore` 済み）。

確認している内容:

| テスト | 何を見ているか |
|---|---|
| 単元選択が科目ごとに保存される | 社会↔理科を往復・リロードしても絞りこみが残るか |
| 全単元を外した状態も復元される | 復習ミックスだけで出題する使い方が保てるか |
| 復習ミックスの単元が科目またぎで保持される | 別科目の選択を消していないか |
| 旧形式の設定からの移行 | 古い保存データ・こわれた保存データでも起動するか |
| 復習編への正誤記録の引きつぎ | 引きつぎ先が実在するか、二重に加算しないか、退避があるか |
| 正解日のない古い記録を補う | 「まだ正解なし」と誤表示されないか |
| やり直しラウンドで正解しても苦手のまま | 何度も間違えた問題が正解ずみに化けないか |
| 一覧の2つの日付を表示・編集できる | 日付を直しても正誤の回数が変わらないか |
| CSVの書き出しと読み込みで記録が失われない | 往復で復元されるか、box/nextDueが壊れないか |
| 復習ミックスの優先順位 | ①未正解 →②いま苦手 →③それ以外、の順になるか |
| 基本の通し | 出題・判定・ホーム復帰・問題一覧が動くか、JSエラーが出ないか |

**このテストでは対戦の通信そのものは確認できません。** WebRTCのライブラリを
スタブに差し替えて起動だけ通しているためです。そこは下の3で見ます。
（`tools/test_reveal_sync.mjs` は、2台の端末を模して「こたえの同時オープン」だけを確かめています）

### 3. 対戦が始められるかの確認（17件・約2分・playwright とインターネットが必要）

```
node tools/test_battle_start.mjs
```

**スタブを使わず、本物の通信ライブラリ（trystero）をインターネットから読み込ませて**
「二人で始める」を押し、**中継サーバーへ実際につながるところまで**確かめます。
（画面の「相手を待っています」は読み込みを待つ前に出てしまうので、それだけでは証拠になりません）

| 場面 | 何を見ているか |
|---|---|
| 先読みずみ | 画面が出て数秒おいてから押したとき |
| 起動直後に押す | 裏の先読みが終わる前に急いで押したとき |
| 読み込みが1回失敗 | 自動でやり直し、押すころには間に合っているか |
| 先読みが完全に失敗 | それでも押したときにやり直して始められるか |

**通信ライブラリの読み込み方を変えたときは、必ずこれを流してください。**
ここを変えると「ひとり練習はできるのに対戦だけ始められない」という壊れ方をします。

なお、**2台目をつないだ実際の対戦は、これでも確認できません。**そこは実機で見てください。

## クイズデータの取り込み

```
python tools/import_quiz.py --list      # 全編の状態を一覧
python tools/import_quiz.py --check N   # 取り込まずに検証だけ（必ず先にこれ）
python tools/import_quiz.py --apply N   # 実際に data.js を書きかえる
```

**問題の id は、元データJSONの `id` フィールドをそのまま使います。配列の位置から採番しません。**
位置から採番すると、既存の問題の中身が別の問題に入れかわり、解答履歴が別の問題に紐づきます
（復習編1では102件中51件で id と位置がずれていました）。
`id` フィールドが無い元データは**既定でエラーにして止まります**。

`--apply` では、画像のコピーと `index.html` の `IMG_SIZES`（画像の幅・高さ）の更新も一緒に行います。

**元データを直している最中は取り込まないでください。**取り込み中に元データが書きかわると、
配信と元データがずれます（取り込み後の照合で気づけますが、照合を省くと見落とします）。

## 通信のしくみ

- `index.html` 内で `https://esm.run/trystero` から Trystero をESM importして使用（ビルド不要）
- 部屋作成時に発行される4桁の数字コードが、そのままTrystero上の部屋IDになる。コードとアプリ固有のappIdの組み合わせで部屋が識別されるため、通常の利用では他の利用者と部屋がぶつかることはない
- 早押しの勝敗判定は「部屋をつくった側（ホスト）」が一元的に決定し、両者に結果を通知することで、双方の端末の時計のずれに影響されず一意に決まるようにしている
- 通信キャリアの回線状況によっては、まれにP2P接続が確立できない場合がある。問題が頻発する場合はFirebaseなど別のシグナリング手段への切り替えを検討する
