# クラウドで直すとき（このリポジトリを、クラウドのセッションで直す人へ）

スマホなどから開いたクラウドのセッションで、このアプリ（kosukequiz-battle）を直すときの決まりです。
自宅PCの担当とは、できることが少しちがいます。

## 1. master には push しない。ブランチを作って、プルリク（PR）を出す

- 作業を始めるときに、新しいブランチを作ります（例: `git checkout -b study-log origin/master`）
- 直したらコミットして、**そのブランチを push** し、**master あてのプルリクを出します**
- ★**master への push・マージは、しないでください。**
  司令塔（とりまとめ役）が中身を確かめ、**ユーザーの承認をもらってから**公開します。
  master はそのまま GitHub Pages で子どもの端末に配られるので、確かめる前のものが出ると困るためです
- クラウドの環境は、使い終わると消えます。**作ったものは必ず push とプルリクまで済ませてください**

## 2. 報告はプルリクの説明に書く

プルリクの説明が、そのまま報告になります。次のことを書いてください。

- 何を変えたか（画面・保存のしかた・書き出すファイルなど）
- 新しく増えたファイルや列があれば、その形（見出しの並び）
- 走らせた検査と、その結果（通った数・ひっかかった数）
- **走らせられなかった検査と、その理由**
- 確かめられなかったこと（実機でしか分からないこと など）

## 3. 検査の走らせかた

検査は `tools/` にあります。`node` で走らせます。

| 種類 | 例 | 要るもの |
|---|---|---|
| ふつうの node だけで動くもの | `node tools/test_solo_session_by_id.mjs`・`node tools/verify_data.mjs` | node |
| 本物の Chrome で画面を動かすもの | `node tools/smoke-test.mjs`・`node tools/mikaku/*_probe.mjs` | playwright（`npm i -g playwright`）と Chrome |

- 画面を動かす検査は、**PCに入っている Chrome を使う作り**です（`channel: "chrome"`）。
  Chrome が無い環境では動きません。そのときは「動かせなかった」とプルリクに書いてください
- 多くの検査は**自己テスト**つきです。直す前の index.html で「鳴る（ひっかかる）」ことを先に確かめてから、
  いまの index.html を見ます。自己テストが不合格なら、その検査は当てになりません
- ⚠️ `tools/mikaku/relay_probe.mjs` の ⑤ は、本物の待ち合わせ先に書き込みます。**何度も続けて走らせないこと**（ROLE.md を参照）
- 待ち合わせ（`RELAY_URLS`・`ROOM_CONFIG`・`APP_ID`）に触ったら、`node tools/mikaku/meet_probe.mjs` を通すこと

## 4. Google ドライブは見られません

ROLE.md や作業メモに出てくる `G:\マイドライブ\...` の場所（問題の元データ・依頼書・名簿など）は、
**クラウドのセッションからは読めません。**
読めないものを読んだことにして進めないでください。要るときは、プルリクの説明に「見られなかった」と書きます。

## 5. 問題のデータには触らない

- `data.js`（一問一答）・`daimon_data.js`（大問）・`images/`（図）は**変えないでください**
- これらは、問題を作る担当が元データから取り込んでいます。手で直すと、元データとずれます
- 問題の文章の直しは、アプリの「保存してGitHubに報告する」から出る Issue をもとに、
  GitHub Actions が自動でプルリクを作る仕組みがあります（`.github/workflows/apply-quiz-fix.yml`）

## 6. 記録は消さない

子どもの端末には、正解・不正解の記録（`kq_battle_stats_v1` など）が入っています。
**どんな直しでも、いまある記録が消えたり、別の問題の記録になったりしないようにしてください。**
「正解・不正解の記録をエクスポート（CSV）」の列と形は、機種変更のときの読み込みが頼っているので、変えないでください。
